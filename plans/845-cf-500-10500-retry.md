# Issue 845: Retry Cloudflare 500/10500 during repair publication

## Goal

Let the repair publisher recover from the pinned `cf` CLI's boxed HTTP 500 response when its API errors line carries code 10500.

## Scope

- Confirm the pinned CLI's error rendering before changing the shared transient classifier.
- Extend the existing six-retry boundary for the specific 500/10500 response.
- Cover reads, safe put rechecks, nonmatching 500 responses, and mixed retry budgets with fake runners.
- Update the repair-publish troubleshooting guidance in `docs/OPS.md`.

## Out of scope

- Bucket access, credentials, deployment, and changes to publication guards, order, enumeration, generation verification, or 401 handling.

## Acceptance

- Boxed 500/10500 receives the same 30-second-plus-jitter retry policy as gateway errors.
- A put is retried only after the exact key is proven absent; an existing object is accepted only when its size and MD5 etag match the source bytes.
- Other HTTP 500 responses fail immediately, and the requested install and test commands pass.
