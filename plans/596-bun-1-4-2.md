# Issue 596: Upgrade the pinned Bun toolchain

## Goal

Use Bun 1.4.2 consistently for dependency installation, development, and the
documented delivery gate. Start from `origin/pre` at
`7873b0895569e4cb99cb1e25f1f2637c6b04b740`, after PRs #664 (#594) and #670 (#595)
merged.

## Scope

- Update the root and web package-manager pins, Bun type declarations, all six
  workflow Bun pins, the AGENTS.md verification blocks and checksum source,
  maintained documentation, and the local R2 rehearsal runtime assertion.
- Keep the runtime guard aligned with both package-manager declarations and
  update its regression coverage for Bun 1.4.2 and mismatched pins.
- Update only the Bun type packages in the web lockfile. Inspect `.delivery.yml`
  for a runtime pin; change it only if alignment requires it.

## Out of scope

No framework or unrelated dependency upgrades, product or visual changes, data
coverage expansion, Worker configuration changes, live service mutations,
deployments, merges, protected-branch pushes, force-pushes, shared-branch rebases,
branch deletion, or GitHub Actions enablement. Historical verification reports
and completed plans retain their recorded tool versions.

## Steps

1. Read issue #596 and repository rules, fetch `pre`, verify the existing
   toolchain by SHA-256, install frozen web/pipeline dependencies, and commit
   this plan.
2. Update the runtime declarations, guard, tests, type packages, and current
   documentation. Bootstrap Bun 1.4.2 from the official bun-v1.4.2 archives,
   inspect dependency changes, and commit the completed upgrade.
3. Run both AGENTS.md verification blocks on the exact committed head in a
   fresh detached local clone under `.kanban-work/GSC_0025/`. Keep temporary
   files, caches, logs, and generated output within that card directory.
4. Open one PR against `pre` with `Closes #596`, the tested commit and every
   command/result, then hand off to an independent review role without merging.
