# Issue 672: Upgrade Next.js to 16.4.2

## Goal

Upgrade the web application from Next.js 16.3.8 to the latest stable release.
`npm view next version --json` returned `16.4.2` on 2026-10-19.

## Scope

- Pin `next`, `eslint-config-next`, and their matched `@next/*` packages to 16.4.2.
- Preserve React 19.3.0 and OpenNext Cloudflare 1.20.7 if their peer ranges allow it.
- Review the official release notes and upgrade guide against App Router,
  configuration, Google fonts, proxy routing, revalidation, metadata, and images.
- Apply required compatibility fixes and update current framework version docs.
- Preserve unrelated lockfile resolutions.

## Out of scope

No Cache Components migration, new pages, data expansion, deployment changes,
Cloudflare operations, Wrangler or OpenNext commands, CI changes, protected-branch
pushes, force pushes, shared-branch rebases, or PR merges. GitHub Actions stays off.

## Steps

1. Bootstrap the pinned toolchain, install the existing frozen dependencies, and
   commit this plan. Create the issue and retain the card branch based on `pre`.
2. Capture the `origin/pre` fixture-build baseline; upgrade the matched packages,
   review compatibility and the lockfile, update version docs, and commit.
3. Capture English and Japanese home, ranking, and repository screenshots from
   local `next start` fixture builds and commit durable evidence under `plans/`.
4. Run the full AGENTS.md bootstrap, static block, and fixture `bun run build` in
   a fresh detached checkout of the final commit, with all temporary files under
   `.kanban-work/GSC_0070/`. Skip `cf:dry-run` by owner order.
5. Open one PR into `pre` with `Closes #672`, command results, screenshot pairs,
   and limitations; hand the card to the independent review role.

If PR #671 merges during the work, merge `origin/pre` normally and use its pinned
toolchain before final verification.

## Acceptance

## Compatibility review

- App Router and configuration: this existing app does not opt into Cache
  Components or Partial Prefetching. The 16.4 defaults for newly generated apps
  do not require a rendering-model migration here.
- Fonts: `RootShell.tsx` uses supported `next/font/google` imports; fixture builds
  exercise font compilation without replacing the site's typography.
- Proxy: `web/proxy.ts` already exports `proxy`; no middleware rename is needed.
- ISR and revalidation: current route intervals stay in place, and the Next
  invalidation adapter already supplies `{ expire: 0 }` to `revalidateTag`.
- Metadata and share images: route adapters and image handlers await promised
  parameters. The existing unknown-repository share-image guard stays in place.
- Dependencies: Next 16.4.2 accepts React and React DOM `^19.0.0`; the installed
  19.3.0 versions remain valid. OpenNext Cloudflare 1.20.7 accepts
  `next >=15.5.26 <16 || >=16.3.6`, including 16.4.2. This checks declared
  compatibility only; the owner forbids executing the Cloudflare adapter here.
- ESLint already uses flat configuration. The full static job will check any
  changed lint rules and generated Next types.
