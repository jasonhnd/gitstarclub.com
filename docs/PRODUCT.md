# gitstarhub 产品设计

> 本文档定义 MVP 的页面、信息架构、URL 与视觉调性。架构与数据层见 [ARCHITECTURE.md](./ARCHITECTURE.md)。

## 调性

**编辑 / 编年史风格**，不是"数据看板"。

- Serif 标题字体（如 Newsreader / Source Serif / Fraunces），sans-serif 正文
- 大量留白、克制的色彩
- 黑白灰为主，仅一两处弱强调色
- 目的：在一众 GitHub 数据工具里显得"像一本书"，而非"像一个 dashboard"

## URL 结构

| 用途 | URL |
|---|---|
| 首页 | `/` |
| 年度页 | `/2024` |
| 月度页 | `/2024/10` |
| Repo 详情页 | `/r/:owner/:name` |
| 关于页 | `/about` |

原则：**最短、可读、SEO 友好**。

## 三个核心页面

### 1. 首页 `/`

**目标**：一眼传达"整个开源世界的时间脉络"，让访客点进任意一年/月。

**布局（从上到下）**：

1. 标题与一句话（"开源世界的编年史 · 5,248 个 ≥10k star 项目 · 11 年时间轴"）
2. **年份脊柱**：2015 → 当前年，每行一年，横向 bar 宽度 = 全年新增 star 总数
   - 鼠标悬停：显示该年 TOP 3 repo
   - 点击：进入年度页 `/2024`
3. **本月聚焦**：当月 TOP / 当月增速，左右并列
4. **历史上的今天**：3-5 条，自动从历史月度榜挑选拐点事件

### 2. 年度页 `/2024`

**目标**：在年的尺度回顾"那一年开源世界的脉络"。

**布局**：

1. 年度标题
2. **12 个月份格子**（热力图风格，3×4 或 1×12）
   - 颜色深度 = 当月新增 star 量
   - 点击进入月度页
3. 年度 TOP 50 榜单
4. 年度新晋成员（首次突破 10k 的 repo）
5. 上下年导航 `← 2023 | 2025 →`

### 3. 月度页 `/2024/10`

**目标**：在一页内看完"那个月开源世界发生了什么"。

**布局**：

1. 标题 + 上下月导航（永远在顶部）
2. 一句话总结（"这个月：5,248 个项目共新增 2.3M star · 47 个新晋成员"）
3. **当月日历热力图**（31 天，看出有无爆发日）
4. **三个核心榜单**（同等地位，并列展示）：
   - 🔥 **当月新增 star TOP 20**（绝对值）— 谁最火
   - 🚀 **当月增速 TOP 10**（相对增长率）— 谁在涨
   - 🎂 **本月新晋成员**（首次突破 10k）— 谁刚来
5. **上下月对比**：进入/跌出 TOP 50 的项目
6. 内部链接：榜单里每个 repo → repo 详情页

### 4. Repo 详情页 `/r/:owner/:name`

**目标**：完整看一个项目的"一生"。

**布局**：

1. 标题：`owner / name` + 一句话描述 + 当前 star
2. 元信息条：语言、创建时间、上次同步时间
3. **全历史 star 曲线**，标注关键里程碑
4. **关键里程碑列表**：创建、首次进榜、突破 10k/50k/100k、当前
   - 每个里程碑 → 链接到对应月度页
5. **月度表现表格**：近 N 月 新增 star + 当月排名
   - 月份列每行都是链接到月度页
6. 元信息：topics、GitHub 外链

## 三个核心榜单的定义

| 榜单 | 定义 | 偏向 |
|---|---|---|
| 当月新增 star TOP | `SUM(star_count)` 当月降序 | 已成名大项目 |
| 当月增速 TOP | `当月新增 / 月初star总数` 降序 | 中等规模爆发项目 |
| 本月新晋 | 当月内 `current_stars` 首次 ≥ 10000 | 新血液 |

排重规则：新晋成员不进入"增速 TOP"避免重复展示。

## 视觉/交互细节

- **永远显示上下月/年导航** —— 强化"翻阅"感
- **榜单内的 repo 名 = 内部链接**；星数变化 = 视觉权重；语言 = 弱标签
- **里程碑链接** = 月度页锚点，形成网状内部循环
- 暂不做：搜索（v0.2）、对比（v0.3）、用户系统（later）
