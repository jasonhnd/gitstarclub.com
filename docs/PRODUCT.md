# gitstarhub 产品设计

> 本文档定义 MVP 的页面、信息架构、URL 与视觉调性。架构与数据层见 [ARCHITECTURE.md](./ARCHITECTURE.md)。

## 调性

**纸感编年史风**，不是"数据看板"。目的：在一众暗色 dashboard 数据工具里，纸感 + 衬线让 gitstarhub 一眼不同，契合"编年史"概念。

### 字体

| 用途 | 字体 |
|---|---|
| 标题 | **Fraunces**（variable serif） |
| 正文 | **Inter** |
| 数字 / repo 名 | **Geist Mono** |

### 配色（纸感，非暗色）

```css
--color-bg:      oklch(98% 0.005 90);   /* 暖白，微偏米，像纸 */
--color-text:    oklch(20% 0 0);        /* 近黑 */
--color-accent:  oklch(45% 0.13 250);   /* 单一墨蓝，克制使用 */
--color-rule:    oklch(85% 0 0);        /* hairline 分隔线 */
```

### 质感

- 极弱纸张纹理（噪点 overlay，opacity < 3%）
- hairline 分隔线（像报纸栏目），**不用卡片阴影堆叠**
- 用线和留白分隔，不用 box-shadow

> 暗色 / 极客风明确放弃——谁都在做。

## URL 结构

| 用途 | URL |
|---|---|
| 首页 | `/` |
| 年度页 | `/2024` |
| 月度页 | `/2024/10` |
| Repo 详情页 | `/r/:owner/:name` |
| 关于页 | `/about` |

原则：**最短、可读、SEO 友好**。

## 三个核心页面

### 1. 首页 `/`

**目标**：一眼传达"整个开源世界的时间脉络"，让访客点进任意一年/月。

**布局（从上到下）**：

1. 标题与一句话（"开源世界的编年史 · 5,248 个 ≥10k star 项目 · 11 年时间轴"）
2. **年份脊柱**：2015 → 当前年，每行一年
   - 每行 = bar（宽度 = 全年新增 star）+ 全年星数 + **一句年度标签**
   - 年度标签：MVP 人工手写 11 条（如 "2024 · AI 元年 · claude-code, ollama 崛起"），v0.2 LLM 化
   - 点击：进入年度页 `/2024`
3. **本月聚焦**：当月 TOP / 当月增速，左右并列
4. **历史上的今天**：3-5 条
   - 实现：取 `first_crossed_10k` 命中今天"月-日"的 repo，按当时 star 量排序
   - 更聪明的影响力排序留 v0.2

### 2. 年度页 `/2024`

**目标**：在年的尺度回顾"那一年开源世界的脉络"。

**布局**：

1. 年度标题
2. **12 个月份格子**（热力图风格，3×4 或 1×12）
   - 颜色深度 = 当月新增 star 量
   - 点击进入月度页
3. 年度 TOP 50 榜单
4. 年度新晋成员（首次突破 10k 的 repo）
5. 上下年导航 `← 2023 | 2025 →`

### 3. 月度页 `/2024/10`

**目标**：在一页内看完"那个月开源世界发生了什么"。

**布局**：

1. 标题 + 上下月导航（永远在顶部）
2. 一句话总结（"这个月：5,248 个项目共新增 2.3M star · 47 个新晋成员"）
3. **当月日历热力图**（31 天，看出有无爆发日）
4. **三个核心榜单**（同等地位，并列展示）：
   - 🔥 **当月新增 star TOP 20**（绝对值）— 谁最火
   - 🚀 **当月增速 TOP 10**（相对增长率）— 谁在涨
   - 🎂 **本月新晋成员**（首次突破 10k）— 谁刚来
5. **上下月对比**：进入/跌出 TOP 50 的项目
6. 内部链接：榜单里每个 repo → repo 详情页

### 4. Repo 详情页 `/r/:owner/:name`

**目标**：完整看一个项目的"一生"。

**布局**：

1. 标题：`owner / name` + 一句话描述 + 当前 star
2. 元信息条：语言、创建时间、上次同步时间
3. **全历史 star 曲线**，标注关键里程碑
4. **关键里程碑列表**：创建、首次进榜、突破 10k/50k/100k、当前
   - 每个里程碑 → 链接到对应月度页
5. **月度表现表格**：近 N 月 新增 star + 当月排名
   - 月份列每行都是链接到月度页
6. 元信息：topics、GitHub 外链

## 三个核心榜单的定义

| 榜单 | 定义 | 偏向 |
|---|---|---|
| 当月新增 star TOP | `SUM(stars_gained)` 当月降序 | 已成名大项目 |
| 当月增速 TOP | `当月新增 / 月初总数` 降序，**月初总数 ≥ 20,000** 才入选 | 已有体量却仍在加速的中坚 |
| 本月新晋 | 当月内 `total_stars` 首次 ≥ 10000 | 新血液 |

**增速榜的 floor（月初 ≥ 20k）**：没有 floor 时增速榜永远是"刚进榜小项目榜"，与新晋榜重复。加 floor 后它变成"已有体量、却还在加速变大的中坚项目"，信息量独立。

排重规则：新晋成员不进入增速 TOP，避免重复展示。

## Repo 身份与改名

- 主键用 GitHub repo **id**（不可变）；URL 用当前 `owner/name`
- repo 改名/迁移：每周白名单刷新时被动更新 `full_name`，旧 URL 做 **301** 重定向
- MVP 不主动追踪完整改名历史（量小，不值得投入）

## 多语言（i18n）

优先级：**英文（为主） > 日文 > 中文**。

- 默认英文在根路径 `/`、`/2024/10`；日文 `/ja/...`；中文 `/zh/...`
- 英文是 `x-default`（hreflang）
- **翻译范围**：UI chrome、导航、年度标签、About、meta/OG 文案
- **不翻译**：repo 名、描述、语言、topic、数字（数据语言中立，保留原文）
- 三语各自独立静态页（SEO 需要），页面总数 × 3 ≈ 16,200（见 [SEO.md](./SEO.md) 与 ARCHITECTURE build 策略）
- MVP 可先做英文，日/中文为紧随其后的第一批增量；i18n 结构从一开始就预留（路由 + 文案字典），避免后期返工

## 项目命名

保持 **gitstarhub**。名字是最容易改的东西，先做出来；品牌/域名后续再议。

## 视觉/交互细节

- **永远显示上下月/年导航** —— 强化"翻阅"感
- **榜单内的 repo 名 = 内部链接**；星数变化 = 视觉权重；语言 = 弱标签
- **里程碑链接** = 月度页锚点，形成网状内部循环
- 暂不做：搜索（v0.2）、对比（v0.3）、用户系统（later）
